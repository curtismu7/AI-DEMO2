## Start here — one thing is NOT done

### 1. `/transaction-trace` shows ONE chain — DONE 2026-08-17 (PR #1921)

**Status: RESOLVED and verified live. The diagnosis below this line is kept only
as a record of what was believed at handoff time — it was WRONG. Do not act on it.**

Post-fix, every ledger record carries a `demo-api-server` hop; the orphan
`mcp-server + ping-gateway` and bare `ping-gateway` clusters are gone. Proof
record:

```
BFF:ui.request(POST /api/path/vertical-tool) | BFF:backend.request(...) | BFF:response(200)
  | mcp-server:mcp.tool(list_orders) | ping-gateway:gateway.authorize(list_orders)
```

**There is no lost AsyncLocalStorage context.** ALS is intact inside every
request — the proof is that the gateway and mcp-server hops already shared an id
derived from it, and `oauth-mcp`'s own `emitHop` reads the same ALS successfully.
Nobody should go hunting for an ALS-dropping async boundary (SSE handler,
LangChain executor, stored callback); there isn't one. Threading the id as an
explicit parameter was also unnecessary.

The real cause was two **request boundaries nobody instrumented**:

1. `POST /api/mcp/tool` (inline handler in `server.js`) had no
   `transactionTurnMiddleware` — only `/api/demo-agent`, `/api/agent` and
   `/api/path` did. The BFF emitted no hop at all for the request that starts
   every chip-fired and direct tool call, so the gateway/MCP hops it caused
   landed in a record with no `demo-api-server` hop.
2. The MCP server calls back into the BFF at `/api/path/vertical-tool`
   (`oauth-mcp/src/banking/BankingAPIClient.ts`) and sent no correlation header,
   so `correlationIdMiddleware` minted a fresh id and filed that leg separately.

Fix was two source lines: mount the turn middleware on `/api/mcp/tool` (after
`requireSession`, so an unauthenticated probe cannot burn the 500-record cap),
and stamp `X-Correlation-ID` from ALS in `BankingAPIClient`'s axios **request
interceptor** — per request, not in the `axios.create` defaults, because one
client instance serves many turns.

Generalisable lesson: when a ledger cluster looks orphaned, first ask *which HTTP
request emitted it, and is that route mounted with `transactionTurnMiddleware`* —
the ledger only sees routes that are.

**How it was verified (unit tests cannot catch this):**

```bash
# 1. drive a REAL tool call through the UI (see "Playwright recipe" below)
# 2. read the ledger directly:
docker exec ai-demo-api-server node -e "
const l=require('/app/services/lmdb/transactionLedger.lmdb');
const recs=l.listRecords({limit:40})||[];
const combos={};
for(const r of recs){const f=l.getRecord(r.correlationId); if(!f)continue;
  const s=[...new Set((f.hops||[]).map(h=>h.service))].sort().join(' + ');
  combos[s]=(combos[s]||0)+1;}
Object.entries(combos).sort((a,b)=>b[1]-a[1]).forEach(([k,v])=>console.log(String(v).padStart(4),k));
"
```
Success = one combo containing `demo-api-server + ping-gateway + mcp-server`.

Note `listRecords()` returns SUMMARIES only (no hops inline) — you must call
`getRecord(correlationId)` for the hop array. That cost me a wrong conclusion early.

## Traps this session cost real time — do not repeat

- **`docker cp` into a bind-mounted path writes THROUGH to the main checkout.**
  I used it to hot-load a fix for fast validation and silently dirtied the
  shared checkout, which made `sync-main-checkout.sh` back off (and would have
  kept the launchd job backing off every 15 min). Cleaned up. Use a worktree +
  merge + `deploy-live.sh` instead.
- **`:latest` push does NOT roll the K8s frontend pod** (manifest unchanged).
  The SE rename check failed on one page purely because the pod was a day old.
  `kubectl rollout restart deploy/frontend -n ping-devops-cmuir` after any push.
- **`git checkout <branch> -- <file>` silently reverts uncommitted work** in that
  file. Bit me once; caught it by grepping straight after.
- **Attribute test failures before fixing.** Every "failure" I chased this
  session was a pre-existing parallel-load flake. Always re-run the named suites
  serially (`--maxWorkers=1`) and compare against clean `main` before blaming
  your diff. Confirmed flaky at least once each: `gateway-passthrough`,
  `gateway-auth`, `delegationApproval`, `logs`, `healthInventory`,
  `rfc9728-integration`, `transactions.crud`, `TransactionConsentModal`,
  `AgentFlowHistoryPage`.
- **Jest regenerates ~443 artifacts** under `demo_api_server/data/`. Never
  `git add -A` after a BFF run; stage explicitly.
- **Worktree cwd drifts back to the main checkout** between Bash calls. Re-pin
  with `EnterWorktree path=<same>`; use absolute paths.
