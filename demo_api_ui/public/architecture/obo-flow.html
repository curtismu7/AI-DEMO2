On behalf of the member: the personal-agent flow

A member's agent acts for them without ever holding their credential. A trusted token service exchanges the member's token and the agent's own identity (RFC 8693) for a short-lived delegated token that names both. Numbers match the trace on the OBO demo page, which runs this flow live.

What the delegated token says

subthe member (unchanged from sign-in)
act{ "client_id": "<agent>" }, the agent that acts
audone downstream API, narrower than the sign-in token
scopeonly what the task needs (obo:invoke in the demo)
expminutes

Why it holds

  • Delegation, not impersonation: audit shows member and agent, not the member alone.
  • Member's own token is refused by the downstream: wrong audience, no act.
  • The agent, the model and the browser never see either token.
  • Revoke the agent's client and delegation stops; the member's session is untouched.

Setup it needs in PingOne

  • A resource for the downstream audience and scope.
  • An AI Agent app (actor) with client credentials.
  • A separate Token Exchanger app allowed to do token exchange.
  • A token-exchange policy that maps act to the actor's client_id.
  • The member must sign in through a client the exchange policy trusts, or the subject token is rejected.
Verified live: 7 of 7 checks pass in the demo (sub preserved, act names the agent, audience narrowed, downstream accepts the delegated token and refuses the member's own, no token text returned).
