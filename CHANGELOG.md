# Changelog

All notable changes to Super Banking are documented here.
Format: [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).
Versions use calendar dates: `YYYY.MM.DD`.

**On every change:**
1. Add one line under `[Unreleased]` in the right category below.
2. If a feature was added or removed, update `FEATURES.md` (including the `Test file` column).
3. If fixing a bug, add a test and an entry to `REGRESSION_LOG.md`.
4. Commit with a conventional prefix: `feat:`, `fix:`, or `chore:`.

**On every production deploy:** run `npm run release` — it versions the `[Unreleased]` section and creates a git tag.

### Changed

### Fixed
- **LMDB storage layer — newest-first paging, audit defaults, DB ceiling** — `reportStore.listRuns`/`listAllRuns`: keys are `${userId}:${runId}` (random UUID), capping the scan before sorting returned arbitrary rows and could drop the newest runs; fixed to collect all, sort by `startedAt` desc, then slice. `bankingDb.getTransactionsByUserId`: ascending key scan + mid-scan cap returned the oldest n; fixed to reverse+slice after collecting the full user range. `mcpAuditStore.append`: spread after defaults let a caller's explicit `undefined` eventId/timestamp clobber generated fallbacks; spread first. `openEnv.maxDbs` raised 16→32 (banking DBs would hit the ceiling). `services/lmdb/{reportStore,bankingDb,mcpAuditStore,openEnv}.lmdb.js`.
- **P1AZ ↔ Agent Gateway connection bugs (gateway + PingGateway groovy)** — the Node gateway omitted `UserId` + `McpResourceUri` from every PingOne Authorize decision (both `buildAuthorizeParameters` for tools/call and the inline `guardToolsList` body for tools/list), so against real cloud P1AZ the `HasValidUserId`/`HasValidMcpAudience` policy conditions failed and every request was denied — the BFF and PingGateway groovy already send both. The PingGateway `p1az-decision.groovy` cached the worker `client_credentials` token in the per-request `binding` instead of the cross-request `globals` store (refetching on every real-backend call) and floored its TTL at 30s; reported `TokenAudActual` as the gateway URI (always equal to `TokenAudience`, defeating any audience-mismatch rule) instead of the real introspected `aud`; and mapped `tools/list` to the catch-all `McpRequest` rather than `McpToolsList`. `guardToolCall` (WS tools/call) gained real→mock failover for parity with the HTTP path. `olb-token-exchange.groovy` now forwards the MCP server's real status (e.g. a 403 HITL challenge) instead of flattening every non-200 to 502. Removed the dead/misleading orphan `client-post-auth.groovy`; `check-groovy-params.sh` no longer false-positives on `decisionEndpoints` inside a comment. `demo_mcp_gateway/src/auth/PingOneAuthorizeClient.ts`, `demo_mcp_gateway/src/pingAuthorizeGuard.ts`, `ping-gateway/scripts/groovy/{p1az-decision,olb-token-exchange}.groovy`, `ping-gateway/scripts/check-groovy-params.sh`.
- **Auth audit follow-ups — invest scopes, gateway auth-method default, stale tenant in docs** — (1) `demo_mcp_invest` advertised `scopes_supported: ['read','write','admin']` in its RFC 9728 metadata, but every invest tool requires `invest:read` — a client trusting the metadata requested the wrong scope and saw zero tools; corrected to `['invest:read']`. (2) `demo_mcp_gateway` `loadConfig()` defaulted `tokenEndpointAuthMethod` to `basic`, but the gateway's OAuth client is a PingOne WEB_APP (CLIENT_SECRET_POST) — defaulted to `post` so a fresh deploy works without an explicit override. (3) Replaced the stale `d02d2305…` PingOne environment id with the current `01d89b06…` across eight active docs/skills (`PINGONE_CONFIG.md`, `AUTHORIZATION_RULES.md`, `pingone-mcp-server`/`mcp-server`/`copilot-studio` skills, etc.) so copy-paste `curl`/config examples hit the right tenant. `demo_mcp_invest/src/index.ts`, `demo_mcp_gateway/src/config.ts`, docs/skills.
- **Auth audit fixes — `.env.example` audience drift + invest signature-skip guard** — three committed `.env.example` files advertised `MCP_GW_RESOURCE_URI=https://api.ping.demo` / `MCP_OLB_RESOURCE_URI=https://api.ping.demo`, but PingOne issues tokens with the bare audiences `mcpgateway.ping.demo` / `mcpserver.ping.demo` (per `scope-topology.json`) — so a fresh setup from the template hit `401 invalid_aud` on every gateway call. Corrected `demo_mcp_gateway/.env.example` (both lines) and `demo_agent_service/.env.example`. Separately, `demo_mcp_invest` was the only token-validating service whose `SKIP_TOKEN_SIGNATURE_VALIDATION` escape hatch had no production guard (just a `console.warn`); added the same startup fail-fast (`process.exit(1)` when set with `NODE_ENV=production`) that `demo_api_server` and `demo_mcp_server` already enforce. `demo_mcp_gateway/.env.example`, `demo_agent_service/.env.example`, `demo_mcp_invest/src/index.ts`.
- **MCP Gateway — `WWW-Authenticate` advertises a reachable `resource_metadata` URL so MCP OAuth auto-discovery works** — the gateway's 401 built `resource_metadata` from `gatewayResourceUri` (`mcpgateway.ping.demo` — the bare audience id, no scheme/host), so an MCP client (Claude Code's `banking-gateway`) couldn't fetch the RFC 9728 metadata and its OAuth handshake failed ("SDK auth failed"). A new shared `selfBaseUrl(req)` helper derives the URL from the request's own scheme+host (honoring `x-forwarded-proto`/`x-forwarded-host`), e.g. `http://api.ping.demo:3005/.well-known/oauth-protected-resource` — which the gateway already serves and which already names the PingOne authorization server. Applied to `GatewayServer.sendUnauthorized` (no-token 401) and the four `authorizeMcpRequest` middleware 401/403 paths (revoked / introspection-failed / policy-violation / authz-deny), which additionally pointed at a non-existent `/.well-known/mcp-server` path. Clients can now complete the browser auth-code+PKCE flow (no copied bearer token). `demo_mcp_gateway/src/selfBaseUrl.ts`, `demo_mcp_gateway/src/server/GatewayServer.ts`, `demo_mcp_gateway/src/middleware/authorizeMcpRequest.ts`.
