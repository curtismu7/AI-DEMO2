# Docker-Based Startup Guide

## Overview

The AI Demo runs best in Docker to avoid port conflicts and ensure clean isolation. All services (API, UI, MCP Server, LangChain Agent, etc.) run in containers with proper networking.

## Quick Start

### 1. Bootstrap PingOne Configuration (First Time Only)

```bash
cd demo_api_server
npm run pingone:bootstrap
cd ..
```

This creates `demo_api_server/.env` with PingOne credentials.

### 2. Start Everything with Docker

```bash
./run-docker.sh
```

This will:
- ✅ Stop any existing containers
- ✅ Generate TLS certs if missing
- ✅ Build and start all services
- ✅ Wait for services to become healthy

### 3. Access the Demo

- **UI**: https://api.ping.demo:4000
- **Admin Login**: https://api.ping.demo:3001/api/auth/oauth/login
- **Code Explorer**: https://api.ping.demo:4000/code-explorer

## Services & Ports

| Service | Port | Type | Access |
|---------|------|------|--------|
| Demo API Server (BFF) | 3001 | HTTPS | Internal |
| Demo UI | 4000 | HTTPS | Browser |
| Demo MCP Server | 8080 | WebSocket | Internal |
| LangChain Agent | 8888 | FastAPI | Internal |
| MCP Gateway | 3005 | HTTP | Internal |
| Agent Service | 3006 | HTTP | Internal |
| HITL Service | 3009 | HTTP | Internal |
| Auth Server | 9001 | HTTP | Internal |

## Common Commands

```bash
# Start everything (stop first)
./run-docker.sh

# Stop all containers
./run-docker.sh stop

# Restart a single service (e.g., langchain-agent)
./run-docker.sh restart langchain-agent

# View logs (all services)
./run-docker.sh logs

# View logs for one service
./run-docker.sh logs langchain-agent

# Check service health
./run-docker.sh status

# Rebuild images and restart
./run-docker.sh build
```

## LangChain Agent (Code Explorer)

The LangChain Agent service provides the CodeGraph feature for `/code-explorer`.

### Configuration

The agent runs in a Python container with:
- **Port 8888**: FastAPI endpoint (CodeGraph API)
- **Port 8889**: WebSocket for chat
- **Port 8890**: Health check endpoint

### How It Works

1. **Container Setup**: `langchain_agent/Dockerfile` builds the Python environment
2. **Startup**: `langchain_agent/scripts/startup.sh` initializes the service
3. **BFF Integration**: `demo_api_server/.env` contains:
   ```
   LANGCHAIN_AGENT_HTTP_URL=http://langchain-agent:8888
   ```
   This allows the BFF to reach the agent via Docker's internal network

### Testing CodeGraph

```bash
# Check if agent is healthy
curl -s http://localhost:8890/health

# Test CodeGraph query endpoint
curl -X POST http://127.0.0.1:8888/codegraph/query \
  -H "Content-Type: application/json" \
  -d '{"question":"What files are in the src directory?", "history":[]}'
```

## Troubleshooting

### Services Won't Start

```bash
# Check what's using the ports
lsof -i -P -n | grep LISTEN

# Stop conflicting processes (e.g., OrbStack)
orbctl stop
```

### Code Changes Not Reflecting

By default, Docker Compose uses `docker-compose.override.yml` for hot reload:
- **UI**: Vite dev server with HMR
- **BFF**: Node --watch for automatic restart

To disable and run production mode:
```bash
PROD_MODE=1 ./run-docker.sh
```

### Container Logs

```bash
# All logs
./run-docker.sh logs

# Follow langchain-agent logs
./run-docker.sh logs -f langchain-agent

# Last 50 lines
docker compose logs --tail=50 langchain-agent
```

### Rebuild Specific Service

```bash
# Rebuild and restart langchain-agent
./run-docker.sh build langchain-agent

# Rebuild all
./run-docker.sh build
```

## Environment Files

- **`demo_api_server/.env`**: Main configuration (PingOne credentials, secrets)
  - Generated by bootstrap
  - Loaded by all services via BFF

- **`langchain_agent/.env`**: Python agent configuration
  - Optional: for LLM keys and custom settings

## Development Workflow

### Local Changes

1. Make changes to source code
2. Docker hot reload picks up changes automatically (if using override)
3. Changes reflect without rebuilding

### Persistent Data

- **`./data/persistent/`**: BFF LMDB store (config, sessions, accounts)
- **`./data/backups/`**: Runtime data backups
- These survive container restarts

## Notes

- **TLS Certs**: Generated via `mkcert` in `certs/` directory
- **DNS**: Add to `/etc/hosts` if needed: `127.0.0.1 api.ping.demo`
- **OrbStack**: If running, stop it first to free ports: `orbctl stop`
- **Docker Desktop**: Requires Docker to be running with ~4GB available memory

## Docker Compose Files

- **`docker-compose.yml`**: Production configuration
- **`docker-compose.override.yml`**: Development overrides (Vite HMR, node --watch)
  - Applied automatically unless `PROD_MODE=1`
