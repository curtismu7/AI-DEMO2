16 / AI functionality

What uses an LLM—and what does not

Heuristics route known commands; models interpret open text and power agent reasoning.

Intent routing

  • Heuristic phrase parser runs for known commands and chips.
  • LLM can return structured action intent for free-text requests.
  • Heuristic fallback keeps common flows available if the LLM route fails.
  • Prompt guard checks configured attack patterns before the LLM call.

Providers / local servers

  • Ping AI / Helix
  • OpenAI
  • Anthropic Claude
  • LM Studio and llama.cpp / oMLX local model modes
  • Ollama in Kubernetes profile; optional proxy fallback where configured

Reasoning and retrieval features

  • Multi-turn LangChain agent runs and conversation history
  • Alternate runtimes explored with OpenAI Agents SDK, Mastra and Pydantic AI
  • Protected code search / Code Explorer
  • Document RAG and knowledge-grounding paths
  • Reasoning/tool activity streamed through AG-UI and traces

Non-LLM enforcement

  • LLM output does not grant OAuth scope.
  • BFF, gateway and resource server validate identity, audience, scope and policy.
  • HITL/MFA stops a write tool until the approval path is satisfied.

17 / Identity and authorization

Authentication controls present in code

Authentication is several different flows—not one login button.

Login: OAuth 2.0 / OIDC authorization code + PKCE; state and nonce checks.
Session: server-side access, refresh and ID tokens; httpOnly session cookie.
Exchange: RFC 8693 subject-token exchange; optional agent actor / nested act.
Audience: RFC 8707 resource indicator / audience-bound resource token.
Validation: JWT signature/JWKS, RFC 7662 introspection, issuer and scope checks.
Authorization: PingOne Authorize and gateway policy decision; route requires public/user/admin.
Step-up: PingOne MFA/device auth; OTP, Push, FIDO2/WebAuthn/TOTP paths.
Out-of-band: CIBA approval flow for separately configured scenarios.
Intent: PAR + RAR authorization details; DPoP replay demonstrations.
Enterprise MCP: ID-JAG / cross-app access and centralized revocation demos.
PKCE, CIBA and exchange stepsRoute access source of truthAuth route implementations

25 / Ways to run it

Launchers and platforms in the repo

Pick native processes, Compose, or Kubernetes; local clusters run on OrbStack too.

Native on macOS

./run.sh starts the BFF, React dev server, MCP server and agent as local Node/Python processes. No app containers or Kubernetes; PingGateway still uses Docker.

Use for: lightest local development. stop, restart, status and tail manage the processes.

Docker Compose · Docker Desktop or OrbStack

./run-docker.sh starts core + Code Search (RAG). start full starts the full service set; mode demo and mode mcpgw start focused subsets.

Opt-in groups: spiffe, demo-auth, mcpgw, observability, tracing, notebooklm and all. NotebookLM requires an explicit build and is not started by full.

Local Kubernetes · OrbStack or Docker Desktop

Enable Kubernetes, then ./run-k8.sh builds images, deploys manifests and supervises port-forwards. Use mode demo, mode mcpgw, mode full, rag on, status or stop.

OrbStack and Docker Desktop both provide supported local Kubernetes clusters.

Remote Kubernetes + deployment handoffs

AWS EKS: ./run-k8.sh aws-all builds/pushes images and deploys. Ping SE cluster: ./run-pingaws.sh wraps the SE build/deploy/status lifecycle.

Terraform can manage the local Compose lifecycle or hand off into an existing SE namespace.

Separate hosted option: README also documents a Vercel serverless deployment for the web app; it needs external Upstash session storage and an external WebSocket MCP server. It is not the same full multi-service deployment as local Compose/Kubernetes.

31 / Privilege AI Gateway

Optional PingOne MCP Gateway · tool access and policy

A governed MCP boundary with discovery, least-privilege decisions and session records.

What the gateway path adds

  • React page at /privilege-mcp-client; BFF relays MCP at /api/privilege-mcp/*.
  • User mode uses OAuth code + PKCE; simple mode uses a service client-credentials token.
  • MCP handshake and tool discovery: initialize, tools/list, then tools/call.
  • The gateway is a server to the BFF and a client to each backend; policy is applied between those sessions.
  • Per-application tool policy, just-in-time least privilege, and session recording.
  • BFF SSE events show OAuth phases, relayed calls and upstream responses.

35 / One request through the stack

Source-traced flow · not a live run

A protected tool call moves through six explicit boundaries.

1 · AskReact sends the prompt to the BFF with the browser session cookie.
2 · CheckBFF validates session and route state, then selects the current LangChain runtime.
3 · RunBFF calls langchain-agent:8888/run; AG-UI events stream back to the screen.
4 · ToolLangChain calls the secret-gated BFF /internal/agent-tool endpoint.
5 · AuthorizeBFF exchanges the credential and calls PingGateway; policy may allow, deny or request approval.
6 · ShowMCP/REST result and run events return to the UI and token-chain evidence views.
Credential boundary: the BFF holds browser tokens. The LangChain runtime requests a tool through an internal callback; the BFF performs the credential and gateway work.

36 / Technical choices visible in code

Why the pieces have these boundaries

The implementation favors inspectable identity decisions and swappable demos.

Tokens stay with the BFFBrowser gets a session cookie; the server performs exchange and tool authorization. This keeps provider credentials and user tokens out of model-facing code.
Known commands stay deterministicHeuristics route common phrases and chips. Natural-language interpretation and agent reasoning use configured model endpoints, with fallbacks where implemented.
One active agent frameworkLangChain is the current runtime. OpenAI Agents SDK, Mastra and Pydantic AI remain documented as tested alternatives, not active runtime choices.
Gateway boundaries stay distinctPingGateway is the default tool enforcement path; Node mcp-gateway is an optional demo; Privilege AI Gateway adds managed MCP policy and recording.
Run profiles control the footprintCompose and Kubernetes select RAG, observability, SPIFFE and gateway services as needed; build-heavy or experimental services stay out of ordinary runs.
Each data system has a jobLMDB stores local BFF state, Weaviate serves vector retrieval, and OpenSearch backs the optional MCP search sample. There is no single production bank database.
