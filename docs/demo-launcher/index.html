Start it. Prove it. Teach it.

This local-only page readies the LibreChat demo and gives the next presenter a repeatable path through PingOne, MCP, policy guardrails, and recovery.

Open LibreChat

The canonical browser origin is https://local.ping-devops.com:4000. Use it for PingOne sign-in; do not use a localhost browser URL for this demo.

Ready the demo

Start the full local stack from the repository root with ./run-docker.sh, or use the Start LibreChat action above. The action only starts the fixed local demo stack. It never accepts a command or destination from the browser.

Run the happy path

  1. Open LibreChat at the canonical origin and complete the PingOne sign-in when prompted.
  2. Choose the Policy Guardrails agent from the top agent menu.
  3. Open the MCP servers panel on the left. Select the matching super-sports-gateway server and use its reconnect control if it is not green.
  4. Start a new chat after changing the agent or MCP server, then use one of the prompts below.

Show the controls

MCP server status

A green dot means the server is connected. A yellow dot means it needs attention, commonly authentication. Use the reconnect icon beside that server. Pick only the server that matches the selected agent so its MCP tools are available to the chat.

Bounded recovery

When a tool-dependent agent reports AGENT_EXPECTED_MCP_TOOLS_UNAVAILABLE, use Clear error & reconnect. It starts one fresh connection attempt for the selected MCP server and clears the saved error only after every selected server reconnects successfully.

Teach the guardrails

Expected 403 authorization lesson

A 403 is a policy decision, not a broken chat. It shows that PingOne authorization denied a request the current identity or granted scope may not perform. Keep the response visible, explain which action was protected, then use a permitted read prompt or sign in with the intended demo user.

Expected 503 gateway-outage lesson

A 503 with unavailable MCP tools means the agent is configured for tools but the MCP connection is unavailable. Check the MCP gateway readiness, reconnect the selected server, and use Clear error & reconnect. Do not describe it as an authorization denial.

If something fails

Service readiness is unavailable

From the repository root, check the known local services, then inspect only the affected containers.

npm run demo:launcher
./run-docker.sh status
docker logs ai-demo-mcp-gateway --tail 100
docker logs librechat --tail 100
The MCP gateway is not running

Start the supported demo-auth optional group, then reconnect the matching MCP server in LibreChat.

./run-docker.sh optional start demo-auth
./run-docker.sh status
PingOne sign-in loops or the demo user is rejected

Use a fresh private window and return to the canonical origin. A browser page served from localhost cannot complete this demo's PingOne sign-in contract.

https://local.ping-devops.com:4000
The old error remains after refresh

Use Clear error & reconnect from the failed message. The saved error stays visible when reconnect, authentication, or deletion fails so the presenter can show the real state and retry safely.
