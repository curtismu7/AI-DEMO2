PingOne Privilege · Agent Security

Privilege Agent Field Guide

Ten demo-verified features with presenter lines, demo paths, and the checks to run before every session.

Identity→ Policy→ LLM surface→ MCP surface→ Human control→ Proof

Run the ten features in demo order: register the agent, put policy on it, walk the LLM surface, then the MCP surface, add a human decision, and close on the audit record.

Everything here is live in the AI-DEMO2 SE environment today. The deck is backup; the demo is the evidence.

Identity & policy 01–02

01

Agent Registry

Every agent enrolls with its own key and gets what a human identity gets: an owner, an expiry, a lifecycle, and policy of its own. Expired keys are edit-locked until you bump the expiry, so stale agents cannot linger silently.

Show

The Agent Registry console with the ten enrolled keys, then the /inspect sidecar check. Try editing an expired key to show the lock.

Say

“This agent has an owner and an expiry, the same way your account does.”

02

Per-credential inspection policy

Allow, alert, sanitize, and block attach to the credential or application, not to a network segment. One credential can be in observe mode while another enforces.

Show

Policy config on a specific credential. Set one to alert-only and walk its events.

Say

“Turn on alert-only first. Watch for a week, then flip it to block.”

LLM surface 03–06

03

Virtual keys

The app never holds a provider API key. It holds a virtual key that is useless outside the gateway, and Privilege injects the real Anthropic or OpenAI key server-side. Contrast with a plain ANTHROPIC_API_KEY in a .env file, which the demo stack also has so the difference is visible.

Show

On /privilege-mcp-client: send a prompt, then point at the gateway route and latency line under the reply.

Say

“That route line is the feature. We called Anthropic through Privilege.”

04

Attributable denial

A policy can deny a call before it reaches the provider, and the denial names the provider, the route, and the policy’s own reason. A 403 llm_policy_denied is the product doing its job.

Show

Click Prove the policy on /privilege-mcp-client. It sends a PII prompt that the live llm-response-pii-withhold policy denies, and the panel renders the denial with its reason.

Say

“This is not an error. The policy is the product.”

If Prove the policy returns a normal reply, the policy is not denying that prompt. Fix the policy or the prompt before presenting.

05

Model allowlists at the gateway

A virtual key can be restricted to a subset of its provider’s models, enforced on the chat call itself as a 403. The dropdown lists the provider’s catalog, not the allowlist, so discovering the refusal in front of the room is the demo.

Show

On /llm-gateway, keep the model dropdown on the lane default, then pick a blocked model. The panel reports “Privilege stopped this”, “Denied by policy”, and “Reached the model: no”.

Say

“The refusal took about 40 milliseconds; the allowed call took seconds. Nothing left the gateway.”

06

Three routes, two wire shapes

Anthropic speaks its native Messages API, where system is a top-level field and the anthropic-version header is required. OpenAI and Google speak the OpenAI-compatible shape. That is why the proxy service is three functions rather than one parameterised call.

Show

The three lanes on /llm-gateway. Use the AI Guard Raw Request tab when you would rather show the wire than the console; it prints the gateway’s untouched response.

Say

“Same policy, same gateway, three providers. Only the wire shape changes.”

MCP surface 07

07

MCP tool-call inspection

Inspection covers two surfaces: the model request/response, and the MCP tool-call boundary including tool results. The hostile-mcp side-by-side makes the value obvious.

Show

Run the governed agent and its ungoverned twin (allow-all policy) against the same hostile server. Governed: the three dangerous tool calls come back DENIED. Ungoverned: all ALLOW. Also show that with no policy at all, the answer is DENY ALL.

Say

“Same model, same tools. The only difference is the gateway.”

Gateway policy changes take about four minutes to propagate, so stage this before the session.

Human control 08

08

Human-in-the-loop approvals

Privilege’s native agentapprovals lets a Cedar policy route a high-risk agent action to a human: the agent pauses, an approval request fires, and the action waits for a decision.

Show

Demo the console-native path that works today: approve via Access Request Approvals, and show the action proceeding on the decision.

Say

“The agent pauses, a human decides, and the audit shows who.”

Proof 09–10

09

Attack Lab

Eight attack types run against the real agent at /llm-gateway?tab=attacks. The five headliners: Tool Abuse, Tool Poisoning, Schema Violation, Inter-Agent Abuse, and Malicious Content.

Show

Run Tool Poisoning. Then teach the attribution rule: a result is a Privilege verdict only when it names Privilege as the enforcement component. An authorization denial or a model refusal is not one.

Say

“A block only counts when Privilege signs it.”

“No gateway decision reported” and “unknown reachability” are valid outcomes. Never narrate them as a pass or a block.

10

Audit evidence

Every governed call leaves a Privilege event, and the deck maps events to compliance controls. The audit record is the close of the demo.

Show

Pull the actual Privilege event for the run you just did and read the enforcement-component field aloud.

Say

“If the audit can’t show it, it didn’t happen.”

Before every session

  1. Do not demo the Google lane. Its virtual key is misconfigured in the Privilege console: every call answers 403 wrong_provider, and the key is actually registered against OpenAI with a placeholder upstream credential. Demo Anthropic and OpenAI until it is repointed.
  2. Do not demo Slack/Teams approvals live. The agentapprovals Slack and Teams wiring is unverified. Show the console fallback via Access Request Approvals.
  3. The AIGuard deck is dated 22 September 2026. Recheck detector thresholds, virtual keys, model allowlists, and benchmark figures against the tenant before quoting slides 2–4 and 8.
  4. Re-verify every live claim. Allowlists, policies, and enrolled keys are console config. If a live result differs from this guide, narrate what you observed and update the guide before the next session.
