# PingGateway/IG Vault API-Key Injection — Phase 1 (Foundation) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stand up the vault-key source of truth and the request-time bridge IG will use — two vault entries, a secret-guarded BFF endpoint that serves only those keys, and an IG container that can call that endpoint over verified TLS.

**Architecture:** IG (`ai-demo-ping-gateway`) will fetch the fake backend API keys from the BFF at request time. Phase 1 builds only the plumbing: the encrypted keys in `secrets.vault`, a `GET /internal/vault/service-key` endpoint on the BFF (shared-secret + allow-list), and the mkcert-CA-into-JVM-truststore wiring so IG→BFF HTTPS is trusted. No IG routes or Groovy yet (Phases 2–3).

**Tech Stack:** Node/Express (BFF, Jest+supertest), the repo vault CLI (`scripts/vault.js`, `lib/vault`), Docker Compose, ForgeRock IG container (`ig:latest`, `keytool`).

- [ ] **Step 3: Write the route**

Create `demo_api_server/routes/vaultServiceKey.js`:

```js
'use strict';

// Internal, gateway-only endpoint: serves the demo backend API keys IG injects
// as X-API-Key. NOT under /api/*; NOT browser-facing. Guarded by the shared
// BFF_INTERNAL_SECRET and a hard allow-list so a real secret can never leak.
const express = require('express');
const crypto = require('crypto');
const configStore = require('../services/configStore');

const router = express.Router();

const DEFAULT_INTERNAL_SECRET = 'dev-shared-secret-change-me';
const INTERNAL_SECRET = process.env.BFF_INTERNAL_SECRET || DEFAULT_INTERNAL_SECRET;
const INTERNAL_SECRET_BUF = Buffer.from(INTERNAL_SECRET);

// The ONLY names this endpoint will ever return. Demo backend keys only.
const ALLOWED = new Set(['DEMO_API_RESOURCE_SERVER_KEY', 'DEMO_MCP_RESOURCE_SERVER_KEY']);

function secretOk(presented) {
  const buf = typeof presented === 'string' ? Buffer.from(presented) : null;
  return (
    !!buf &&
    buf.length === INTERNAL_SECRET_BUF.length &&
    crypto.timingSafeEqual(buf, INTERNAL_SECRET_BUF)
  );
}

router.get('/vault/service-key', (req, res) => {
  if (!secretOk(req.headers['x-internal-gateway-secret'])) {
    return res.status(403).json({ error: 'forbidden' });
  }
  const name = String(req.query.name || '');
  if (!ALLOWED.has(name)) {
    return res.status(404).json({ error: 'not_allowlisted' });
  }
  const value = configStore.get(name.toLowerCase());
  if (value === null || value === undefined || value === '') {
    return res.status(404).json({ error: 'key_unset' });
  }
  return res.status(200).json({ name, value });
});

module.exports = router;
```

- [ ] **Step 3: Extend the entrypoint to import the mkcert CA**

Replace the `ping-gateway` `entrypoint:` line. Current:

```yaml
    entrypoint: ["/bin/sh", "-c", "rm -f /var/gateway/tmp/ig.pid && exec /opt/gateway/bin/start.sh /var/gateway"]
```

New (imports the mkcert root into the default JDK `cacerts`; idempotent via `|| true`; `-noprompt`, default store password `changeit`):

```yaml
    entrypoint:
      - /bin/sh
      - -c
      - >-
        keytool -importcert -noprompt -alias mkcert-root -cacerts -storepass changeit
        -file /certs/mkcert-rootCA.pem 2>/dev/null || true;
        rm -f /var/gateway/tmp/ig.pid && exec /opt/gateway/bin/start.sh /var/gateway
```

Fallback (only if Step 1 showed `keytool` is not on PATH or `-cacerts` is unwritable): use the absolute `"$JAVA_HOME/bin/keytool"` and/or a standalone truststore —
`keytool -importcert -noprompt -alias mkcert-root -keystore /var/gateway/mkcert-truststore.jks -storepass changeit -file /certs/mkcert-rootCA.pem 2>/dev/null || true;`
then add `JAVA_OPTS: "-Djavax.net.ssl.trustStore=/var/gateway/mkcert-truststore.jks -Djavax.net.ssl.trustStorePassword=changeit"` to the env block.
