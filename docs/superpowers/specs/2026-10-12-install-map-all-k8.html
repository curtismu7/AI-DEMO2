Everything runs in Kubernetes — the Mac just drives it

The design goal: everything that runs, runs in Kubernetes — and the single-node cluster is actively kept from overloading. A new Mac needs one app install (OrbStack) and a handful of commands. Inside the OrbStack Kubernetes VM live all 20 demo images (built there by docker compose build — nothing comes from a private registry), the LLM runtime and its 20 GiB of models, and the whole observability stack. The Mac keeps only the driver set: tools, the repo and credentials. Load stays bounded through a namespace quota, LLM tiering (one tier active at a time), scale-down modes and on-demand stacks. The steady-state cloud calls are the recipient's own PingOne environment on every sign-in, plus two optional MCP web APIs when those tools run.

Install sequenceFive steps, then it runs

Install OrbStack → enable Kubernetes

The only sizeable app on the Mac. It provides the Docker engine (which the build in step 3 uses) and a single-node Kubernetes cluster; nothing else below runs on the host.

git clone <repo> && cd AI-DEMO2

Manifests, k8s/deploy.sh and docker-compose.yml come from git. certs/ and .env are gitignored and generated locally.

brew install kubectl node && docker compose build

Builds all 20 demo images inside the VM's Docker engine — the long pole, ~28 GB of image cache. Add helm only if keeping the Procyon node sensor.

npm run pingone:bootstrap && ./k8s/create-secrets.sh

Bootstraps the recipient's own PingOne environment (needs node), writes demo_api_server/.env, then turns it into cluster Secrets.

./k8s/deploy.sh && ./k8s/deploy.sh forward

Applies the manifests, seeds LLM models from HuggingFace in-cluster, then forwards ports to localhost. Run k8s/smoke.sh for the pass/fail table.

Keeping the cluster healthyHow "everything in K8s" doesn't overload it

Five mechanisms, all already in the manifests, keep a single-node cluster from tipping over. Nothing here is aspirational.

hard ceiling

Namespace quota

01-namespace.yaml · 48Gi / 16 cores

The whole namespace is capped at 48 Gi RAM and 16 cores (16 Gi / 8 cores with the overlays/small profile for 16 GB Macs). Pods beyond the quota simply don't schedule — the VM can't be eaten by accident.

1 active

LLM tiering

56-llm-stack.yaml · tier-manager

Two llama.cpp tiers (20B primary, 8B fast) but one active at a time — the tier-manager scales one up and the other to zero on demand. The biggest single memory consumer never runs twice.

4 modes

Scale-down modes

deploy.sh mode

basic keeps dashboard + login only; demo runs frontend, BFF, mcp-server and the two gateways; mcpgw runs two pods; full restores everything. extras off sheds the investment/mortgage backends.

on demand

Conditional stacks

deploy.sh rag on · replicas: 0

RAG/weaviate/tika stay at replicas: 0 until rag on. privilege-mcpgw stays at 0 without its secret. On-demand agents start only when invoked. Idle memory is returned by design.

per pod

Per-pod limits

every deployment

Every pod carries explicit memory/CPU limits — the 2 Gi api-server, 4 Gi langchain-agent, 1 Gi python agents — so no single service can starve the rest. The crash-loop protection manifest stops restart storms.

escape hatch

Total shutdown

deploy.sh stop · destroy

deploy.sh stop scales everything to zero (config kept, VM memory freed) without losing the build or models; destroy deletes the namespace entirely. Uninstalling OrbStack removes the rest.

Demo services

built by docker compose build

Frontend, API server (BFF), authz server, MCP server + gateway, LangChain and LlamaIndex agents, HITL service, prompt guard, resource servers, ungoverned agent, tier manager, LLM proxy, weather/brave/jwt-verifier/code-search MCP servers.

2 tiers

LLM stack

ghcr.io/ggml-org/llama.cpp (digest-pinned)

Two llama.cpp tiers (20B primary, 8B fast) with a tier-manager that swaps the active one. Models arrive as GGUF files pulled from HuggingFace by an in-cluster seed job into a 20 GiB PVC — no host-side model download.

2–3 pods

Ping integration

us-docker.pkg.dev · public.ecr.aws (Ping)

PingGateway (ForgeRock ig image) always runs. The Privilege MCPGW is optional: without a Privilege license (and its secret) it stays scaled to zero — the demo loses only the governed per-app MCPGW door, policy enforcement and session recording. The Procyon node sensor installs by default on OrbStack and needs a registered Privilege NHI; skip it with PROCYON_NODESENSOR_ENABLED=0.

6 pods

Observability

docker hub, digest-pinned

Prometheus, Alertmanager, Grafana, Loki, Alloy and Jaeger — the full metrics/logs/tracing stack runs inside the same VM, reachable through its own port-forwards.

on demand

RAG + infra

docker hub, digest-pinned

Weaviate, Tika and the code-search RAG stack start with rag on; Redis and the kubectl/curl job images round out the baseline.

1 namespace

Config, secrets, storage

created from host .env

One ConfigMap drives all services; Secrets are generated on the Mac from the bootstrap's .env; PVCs hold models, API logs and MCP OAuth state.

After the first build and deploy, images and models are cached in OrbStack's VM disk — but the demo is not offline: PingOne answers every sign-in, and the Brave/weather APIs are called whenever those MCP tools run. Low-memory Macs (16 GB) apply the k8s/overlays/small profile, which drops the quota to 16 Gi / 8 cores. For dashboard-only demos, ./k8s/deploy.sh mode demo scales down to frontend, BFF, mcp-server and the two gateways and frees the rest.
