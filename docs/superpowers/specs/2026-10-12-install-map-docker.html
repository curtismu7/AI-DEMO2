Plain Docker: no Kubernetes, no cluster — just containers

The whole demo also runs with nothing but Docker Compose — ./run-docker.sh on OrbStack's engine. No Kubernetes, no manifests, no quotas: 15 core services come up, RAG and demo-auth ride along, and six optional groups (observability, tracing, mcpgw, SPIFFE, JEV, attack) start on demand. The one thing that doesn't go in a container is the LLM: llama.cpp runs as a host process reading GGUFs from ~/models, and the llm-proxy container routes to it over host.docker.internal. Compose reads the bootstrap's .env directly — there is no create-secrets step.

Install sequenceSix steps, then it runs

Install OrbStack

Docker engine + Compose only — Kubernetes stays off in this mode. The only sizeable app install.

git clone <repo> && cd AI-DEMO2

run-docker.sh, docker-compose.yml and the service sources come from git. The script pins its compose project to the main checkout — worktree clones guard against double-stacks.

brew install node llama.cpp mkcert huggingface-cli

Host tooling: node (tier-manager, health gate, bootstrap), llama-server for the LLM tiers, mkcert for TLS. Optional: pingcli, python3.

cd demo_api_server && npm run pingone:bootstrap

Same bootstrap as the K8s path: creates the recipient's own PingOne environment and apps, writes demo_api_server/.env and generates certs/.

/etc/hosts + mkcert -install && bash demo_llm_proxy/download-models.sh fetch

Map api.ping.demo and local.ping-devops.com to 127.0.0.1, trust the mkcert CA, then pull the GGUFs (~13 GB for both tiers; 2.5 GB tier-1 alone is enough to start).

./run-docker.sh

Builds the images, starts core + RAG + demo-auth, runs the health gate, and opens https://local.ping-devops.com:4000/demo-summary. start full adds every optional group; optional start observability adds one.

The mapHost vs VM vs cloud — LLM stays on the host

The host does more work in this mode: it runs the LLM, holds the models and serves the TLS trust. Containers talk to it over host.docker.internal; Apple MLX is native-only and is never used in a Docker context.

Keeping the Mac healthyHow compose mode bounds its footprint

No ResourceQuota exists here — the guardrails are the script's own residency policy and Compose mechanics. All verified in run-docker.sh and the compose file.

by RAM

LLM residency policy

apply-residency-policy.sh

≥32 GB Macs keep both tiers resident (~14 GB). Under 32 GB the script pins the 8B tier on :8091 only — the 20B never loads. The single biggest consumer self-throttles to the machine.

off by default

Optional groups

compose profiles

Observability, tracing, mcpgw, SPIFFE, JEV and the attack agent start only when asked (optional start <group>). Core + RAG + demo-auth is the default footprint; start full is a deliberate act.

~3.75 GB

Observability limits

mem_limit × 6 services

The only containers with memory caps: jaeger 512m, prometheus 1g, alertmanager 256m, loki 1g, alloy 512m, grafana 512m — the heavy log/metrics stack can't starve the demo.

Disk hygiene

post-build prune

Every run-docker.sh build ends with an image/builder prune, so the ~28 GB of dangling intermediates the K8s path accumulates never piles up here.

1 stack

Single-project guard

COMPOSE_PROJECT_NAME=ai-demo

The script pins its compose project and directory to the main checkout and purges stale or foreign containers on start — two clones can't fight over the ports or the volumes.

Host inventoryOn the Mac itself — more than the K8s mode

This is the trade: no cluster, but the host carries the LLM, the models and the TLS trust. Uninstalling OrbStack still removes the demo — the models and brew tools stay behind.

Cluster machinery

not in this mode

Docker-only vs Kubernetes, in one line each: compose mode is lighter to set up (no kubectl, no manifests, no secrets step) and prunes its own disk, but gives up network policy, resource quotas and ingress, and puts the LLM on the host — the Mac's RAM is the real quota, enforced by the residency policy (<32 GB pins the small tier). The K8s mode keeps everything in the cluster at the cost of the manifests and a ~28 GB local build (or the GHCR pull path, DEPLOY_SOURCE=ghcr). Sibling page: docs/superpowers/specs/2026-10-12-install-map-all-k8.html.

Both modes share: the PingOne bootstrap, the same core services, the same runtime cloud calls, and run-docker.sh mode demo|mcpgw|full mirrors k8s/deploy.sh mode.
