AI-DEMO2 · recipient install topology

Where everything lives after install

A new Mac runs the full demo with two manual installs — OrbStack and Homebrew — and one script. Everything heavy stays out of the Mac: the 20 demo images, the LLM runtime and its 20 GiB of models, and the whole observability stack live as pods inside the OrbStack Kubernetes VM. The only steady-state cloud dependency is the recipient's own PingOne environment.

Install sequenceThree steps, then it runs

Install OrbStack → enable Kubernetes

The only sizeable download on the Mac. It provides the Docker engine and a single-node Kubernetes cluster; nothing else below runs on the host.

git clone <repo> && cd AI-DEMO2

Manifests, deploy scripts and skills come from git. Certificates and .env are gitignored and generated locally in step 3.

./k8s/share-setup.sh

Brew-installs kubectl, helm, node if missing → prompts for PingOne worker creds → runs the PingOne bootstrap → creates cluster Secrets → deploys from public GHCR images → seeds LLM models → runs smoke checks.

Cluster inventoryIn the namespace — 5 groups, ~30 pods

Every pod is a pull from a public registry, tagged v1.YYMMDD for ours, digest-pinned for upstream. Nothing is built on the recipient's machine.

20 images

Demo services

ghcr.io/curtismu7 ×11 · ghcr.io/cmuir_pingcorp ×9

Frontend, API server (BFF), authz server, MCP server + gateway, LangChain and LlamaIndex agents, HITL service, prompt guard, resource servers, ungoverned agent, tier manager, LLM proxy, weather/brave/jwt-verifier/code-search MCP servers.

2 tiers

LLM stack

ghcr.io/ggml-org/llama.cpp (digest-pinned)

Two llama.cpp tiers (20B primary, 8B fast) with a tier-manager that swaps the active one. Models arrive as GGUF files pulled from HuggingFace by an in-cluster seed job into a 20 GiB PVC — no host-side model download.

2–3 pods

Ping integration

us-docker.pkg.dev · public.ecr.aws (Ping)

PingGateway (ForgeRock ig image) always runs. The Privilege MCPGW is optional: without a Privilege license (and its secret) it stays scaled to zero — the demo loses only the governed per-app MCPGW door, policy enforcement and session recording. The Procyon node sensor installs by default on OrbStack and needs a registered Privilege NHI; the setup script disables it for recipients.

5 pods

Observability

docker hub, digest-pinned

Prometheus, Grafana, Loki, Alloy and Jaeger — the full metrics/logs/tracing stack runs inside the same VM, reachable through its own port-forwards.

on demand

RAG + infra

docker hub, digest-pinned

Weaviate, Tika and the code-search RAG stack start with rag on; Redis and the kubectl/curl job images round out the baseline.

Config, secrets, storage

created from host .env

One ConfigMap drives all services; Secrets are generated on the Mac from the bootstrap's .env; PVCs hold models, API logs and MCP OAuth state.

After the first deploy, images and models are cached in OrbStack's VM disk — the demo runs offline except for PingOne. Low-memory Macs (16 GB) apply the k8s/overlays/small profile, which drops the quota to 16 Gi / 8 cores. For dashboard-only demos, ./run-k8.sh mode demo scales down to the frontend, BFF and gateways and frees the rest.
