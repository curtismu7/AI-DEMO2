# PDF Report Redesign — Design

Date: 2026-07-10
Status: Approved (engine, color usage, and demo callouts confirmed by user; final
gate could not fire — session went non-interactive — so the PR is the review gate).

## Problem

The `/reports` PDF (generated by `formatPdf()` in
`demo_api_server/services/reportFormatter.js`) is flat run-on `doc.text()` output:
no visual sections, no status color, single-line JSON dumps, uncontrolled page
breaks. The HTML report is already well-structured; the PDF is not usable in a
demo.

## Decisions (user-confirmed)

1. **Engine:** keep pure-JS pdfkit (no Chromium in the container image); rebuild
   the layout in pdfkit primitives. No new dependencies.
2. **Color:** status coloring (green success / red failed / amber skipped /
   gray unknown) AND token-diff coloring across RFC 8693 exchange legs
   (removed scopes red with "−", added claims green with "+").
3. **Demo callouts (all four):** RFC 8693 token exchange, delegation chain from
   nested `act` claims, least-privilege scope narrowing, CIBA/HITL step-up.

## Scope

- Rewrite `formatPdf()` (and add small pure helpers) in
  `demo_api_server/services/reportFormatter.js`.
- Tiny change in `demo_api_server/routes/reports.js`: annotate the run with
  `hasCibaStepUp` (reusing the existing bridge logic) before formatting, so the
  PDF can render the CIBA callout.
- New unit test with a representative fixture run.
- **Untouched:** `formatMarkdown`, `formatHtml`, the React `/reports` page,
  download/share routes, report storage.

## Layout (A4, 50pt margins)

1. **Header band** — dark-blue (#1a5276) filled rect: title, subtitle, vertical,
   date, run ID; rounded status pill (green/red) right-aligned.
2. **Demo Highlights callout** — bordered box under the header; one accented line
   per detected concept: exchange-leg count (RFC 8693), delegation chain
   `user → agent → specialist` (A2A depth noted), scope narrowing ("12 → 3
   scopes"), CIBA step-up badge (amber). Lines appear only when detected.
3. **Summary** — two-column rounded card grid, uppercase labels (mirrors the
   HTML summary grid).
4. **Prompt** — gray inset box, Courier.
5. **OAuth Token Chain** — one card per event: status-colored left accent bar,
   numbered badge, label, pills row (status/type/alg/RFC), claims as a
   two-column key/value table with alternating row shading, exchange steps as a
   numbered list. **Token-diff block** on events whose claims differ from the
   previous claim-bearing event: removed scopes red "−", added scopes/claims
   green "+", audience change amber.
6. **MCP Delegation Trail** — purple (#8e44ad) accented cards; pretty-printed
   JSON request/response in a dark code box at ~7.5pt, truncated past ~40 lines
   with an explicit "… truncated" line.
7. **Metadata table** and a per-page footer: "AI Demo Authorization Audit
   System · Page X of Y" (pdfkit `bufferPages`).

**Page-break control:** each card estimates its height and starts a new page if
it won't fit, so cards never split mid-content.

**Palette** matches the HTML report: #1a5276, #277ba5, #27ae60, #e74c3c,
#f0b429, #8e44ad. No emojis (PDF base fonts have no emoji glyphs).

**Error handling** unchanged: any failure resolves `null`; the route already
falls back (HTML print path).

## Verification / done criteria

1. New Jest test: fixture run (exchange events with narrowing scopes, CIBA
   event, failed event, MCP calls with JSON bodies) → `formatPdf` resolves a
   Buffer starting with `%PDF`, multi-page.
2. Generate the fixture PDF, rasterize pages, visually confirm: distinct
   sections, colored statuses, visible diff block, highlights box, no mid-card
   splits.
3. `npm run test:api-server` (or the reports-scoped subset) stays green.
