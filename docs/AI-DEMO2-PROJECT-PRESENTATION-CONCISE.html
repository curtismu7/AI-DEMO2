Delegated flow

The full delegation sequence across all nine participants.

sequenceDiagram
  autonumber
  actor U as User (browser ui :4000)
  participant BFF as BFF demo-api-server :3001
  participant ID as PingOne (OAuth · MFA)
  participant A as langchain-agent :8888
  participant LLM as llm-proxy :8090
  participant GW as ping-gateway :3036
  participant HITL as hitl-service :3009
  participant MCP as mcp-server :8080 / api-resource-server :8082
  participant AUD as mcp-audit :8898 · jaeger

  U->>BFF: prompt + session cookie (no tokens in page)
  BFF->>ID: session check / OIDC tokens (held server-side)
  BFF->>A: POST /run (AG-UI, SSE open)
  A->>LLM: interpret open text (heuristics skip this)
  A-->>BFF: tool request via /internal/agent-tool callback
  BFF->>ID: RFC 8693 exchange → audience + scope-narrowed tool token
  BFF->>GW: tool call with exchanged token
  GW->>GW: P1AZ policy decision: permit · challenge · deny
  alt write above threshold
    GW->>HITL: consent required
    HITL-->>U: approve / reject (step-up MFA via PingOne)
    HITL-->>GW: approval recorded
  end
  GW->>MCP: authorized MCP / REST call
  MCP-->>GW: result
  MCP->>AUD: tool event · trace
  GW-->>BFF: authorized response
  BFF-->>A: tool result
  A-->>U: answer + token-chain evidence (SSE)
Delegation: user token never reaches agent or tool — BFF exchanges (8693), gateway enforces. Consent is in-band: HITL pauses the gateway path for human approval, with PingOne step-up MFA, before the write proceeds. Every hop is evidenced: token-chain events, mcp-audit tool events and jaeger traces are collected across the run.

09 / One request through the stack

One request, source-traced

A protected tool call passes six explicit boundaries.

1 · AskReact → BFF prompt with session cookie.
2 · CheckBFF validates session, selects LangChain runtime.
3 · RunBFF calls agent /run; AG-UI events stream back.
4 · ToolAgent calls BFF /internal/agent-tool.
5 · AuthorizeBFF exchanges token, calls PingGateway: permit · deny · approval.
6 · ShowResult + events return to UI and token-chain views.
Credential boundary: BFF holds browser tokens; the agent only requests tools via callback.

11 / Standards and RFCs

Protocol surface implemented and exercised in the repo · includes PingOne Authorize (P1AZ)

The demo speaks the OAuth/OIDC RFC stack—not just a login button.

Core authorization

RFC 6749 OAuth 2.0 framework · RFC 6750 bearer tokens · RFC 7636 PKCE · RFC 8693 token exchange — the demo's signature delegation primitive · RFC 8414 authorization-server metadata · RFC 9207 iss parameter · RFC 9700 OAuth 2.0 security BCP

Tokens and revocation

RFC 7519 JWT · RFC 7515 JWS signing · RFC 7638 JWK thumbprint · RFC 7009 token revocation · RFC 7662 token introspection · RFC 9068 JWT access tokens · RFC 8705 mTLS / DPoP-bound credentials · RFC 9449 DPoP

Advanced authorization

RFC 9396 Rich Authorization Requests (RAR) · RFC 9126 Pushed Authorization Requests (PAR) · RFC 7591 dynamic client registration · RFC 7521/7523 JWT client assertion grants · RFC 8707 resource indicators (audience narrowing)

Protected resources and MCP

RFC 9728 Protected Resource Metadata — how MCP clients find OAuth servers · RFC 9470 client-initiated backchannel authentication / 428 re-auth in HITL flows · RFC 9421 HTTP message signatures · RFC 5424 syslog audit events

PingOne Authorize (P1AZ)

Trust framework + policy rules imported via snapshot; TokenActive rules evaluate the actor/act token chain from the RFC 8693 exchanges · Step-up MFA and amount-threshold policies exercised in live flows · p1az-import-generator skill and docs/P1AZ_TOKENACTIVE_RULE_SETUP.md · Agent Privilege policy runtime (slide 33) applies P1AZ decisions at the MCP boundary

Where to see them

Token Chain inspector renders principal/actor/audience/scopes per hop · Authorize decision inspector shows P1AZ rules firing · token lab exercises 7662 introspection and 7009 revocation fail-closed · PAR button on the gateway console sends 9126 pushes · A2A sequence demonstrates nested 8693 exchanges
