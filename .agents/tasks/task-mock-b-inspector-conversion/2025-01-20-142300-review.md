# Mock B dark IDE three-column conversion for 5 inspector components

Five inspector/tester components (McpInspector, AgentGatewayTester, ResourceServerTester, TokenSecurityTester, ApiExplorerPanel) were refactored from heterogeneous layouts — chip grids, collapsible sections, vertical forms, split panels — into a uniform three-column dark IDE layout matching PingOneMcpInspector.js. Each now imports the shared `PingOneMcpInspector.css` and renders the same structural skeleton: left tree sidebar with grouped items and search, center form/detail panel with Execute/Clear, right tabbed output panel with a status footer. Component-specific CSS was gutted down to domain-only overrides.

**Watch for:** The grid's hard-coded `calc(100vh - 45px)` height will clip or overflow in McpInspector because that page wraps the p1mcp-page inside a parent that includes `PageNav` (confirmed, extra ~50px unaccounted). Heavy reliance on inline `style={{}}` objects (50+ occurrences across the diff) bypasses the shared CSS contract and makes future theming brittle (likely). The AgentGatewayTester removed all structured P1AZ attribute tables, audit-filter explanatory copy, and RFC 9728 metadata renderers — that's educational content loss, not just layout change (confirmed).

## High-level view

The layout contract is consistent: every component uses `p1mcp-topbar` → `p1mcp-grid` (tree | form | output). The shared CSS in `PingOneMcpInspector.css` provides the full structural system; per-component CSS files shrink to domain-specific additions (verdict badges, rule lists, method colors).

McpInspector replaces the Read/Write/Reasoning tabs with a flat resource-grouped tree. ResourceServerTester is the most complex rewrite: it multiplexes four operations through a single selectedOp + currentRunner pattern rather than four independent collapsible panels. AgentGatewayTester loses the most non-layout content — structured audit tables and RFC 9728 metadata are now raw JSON dumps in output tabs.

The viewport height calculation in the shared grid assumes the `p1mcp-topbar` is the only element above the three columns, but McpInspector (uniquely among the five) renders a `PageNav` outside the `p1mcp-page` wrapper. The other four components render without PageNav and are unaffected.

<summary>Details</summary>

## Fixed grid with no responsive fallback

The grid uses fixed `grid-template-columns: 240px 380px 1fr` with no responsive breakpoint. On viewports narrower than ~700px the form column will be squeezed; there's no media query or `minmax()` fallback. This matches the reference mock (desktop-only IDE layout) but will clip on smaller screens.

## McpInspector: lost filtering capability

The Read/Write/Reasoning tab system is entirely removed. The new tree groups tools by resource domain using `groupByResource`, which now returns `{ key, label, tools }` objects instead of tuples. There's no longer a way to limit the visible tool set to just write or just reasoning tools except via the search box, which is a functional regression for users who relied on tabs to filter by access level.

The `COLLAPSED_RESOURCES` set (which kept admin/directory/vertical/other groups closed by default) has no equivalent in the tree layout — all groups are always expanded. For large tool catalogs this means more scrolling.

## AgentGatewayTester: config controls inside the navigation tree

Gateway configuration (active gateway toggle, UC18 rate limiting, presets, metadata) lives in a second `treeSection` ('config') switchable via buttons in the tree header. This puts interactive mutation controls (toggle gateway, enable UC18, run burst test) inside what is visually a navigation column. Users clicking items in the tree might not expect some to trigger state mutations rather than item selection.

The burst test action is available in two places: once inside the `config` tree section, and once as a button in the form actions bar (only when `rateStatus?.aligned`). Duplicated affordance with no obvious reason.

## ResourceServerTester: runner state persists across operation switches

The four operations each instantiate their own `useRunner` hook at the top level. Switching operations in the tree shows the result from a previously-executed operation without re-running it. This is inconsistent with the other components (McpInspector, AgentGatewayTester, TokenSecurityTester) where selecting a new tree item clears output.

The `useRunner` hook doesn't expose a `reset` method, so `clearOutput` has to work around this by directly calling state setters for each runner. If a fifth operation is added, someone must remember to add its reset call — the pattern doesn't scale automatically.

## Inline styles vs. CSS classes

AgentGatewayTester has 29 inline `style={{}}` objects, McpInspector has 11, ResourceServerTester has 11. Most set dot colors dynamically (`background: rateStatus.aligned ? '#22c55e' : '#ef4444'`), override font sizes, or add padding. The dark theme's color palette is now split between CSS classes in `PingOneMcpInspector.css` and literal hex values in JSX. If the theme changes, these inline values won't update.
