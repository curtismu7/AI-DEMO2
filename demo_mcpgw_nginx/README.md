# MCPGW front door (nginx)

The "nginx engine" from the PingOne Privilege SE storyboard. Puts customer-owned
DNS and TLS in front of the Privilege gateway runtime so the frontend URL an MCP
client calls is a domain we control:

```
https://banking.mcpgw.local.ping-devops.com/mcp
  -> mcpgw-nginx :443          (this service)
  -> ping-mcpgw  :8623         cyonproxy -listen, "Frontend Name" in the console
  -> mcp-server  :8080         "Backend Name" in the console
```

Compose profile: `mcpgw`. Started with the gateway by
`./run-docker.sh optional start mcpgw`.

## Why this exists

Privilege has two topologies and only one of them works for this demo.

| | mesh / cloud frontend | agentless / self-hosted frontend |
|---|---|---|
| Frontend Name | `*.applications.privilege.pingone.com` (Ping assigns it) | our domain (we choose it) |
| Local listener | none — routed over the outbound gRPC mesh | `cyonproxy -listen :8623` |
| Who authenticates the client | Privilege validates the client's PingOne JWT | the gateway runs the OIDC dance itself |
| `ping-mcpgw/config/pingone.env` | never read | the OIDC config |
| Blocker | `IssuerPublicKey:[]` → `JWT signature validation failed`, unfixable from this repo | none — no issuer trust needed |

Full history in [`docs/PRIVILEGE-MCP.md`](../docs/PRIVILEGE-MCP.md).

## Host setup (one-time)

A wildcard certificate works; `/etc/hosts` has no wildcard. Add one line per
frontend host:

```
127.0.0.1  mcpgw.local.ping-devops.com
127.0.0.1  banking.mcpgw.local.ping-devops.com
```

Certificates are generated by `scripts/ensure-mcpgw-certs.sh` (run automatically
by `run-docker.sh` for the `mcpgw` profile) into the gitignored `certs/` dir as
`mcpgw-wildcard.pem` / `mcpgw-wildcard-key.pem`.

## Adding an MCP Server application

1. Add `127.0.0.1  <app>.mcpgw.local.ping-devops.com` to `/etc/hosts`.
2. Add the alias to `mcpgw-nginx` in `docker-compose.yml` (compose DNS, so the
   BFF's server-side relay resolves it too).
3. In the Privilege console, set the application's **Frontend Name** to that host
   and **Backend Name** to the compose-internal URL (e.g. `http://mcp-server:8080/mcp`).

The wildcard cert and the nginx vhost need no change.

## Port 443

Published as `443:443` so registered frontend URLs carry no port, matching the
vendor's SE material. If something else on the host owns 443, change the compose
mapping to `8643:443` and append `:8643` to every Frontend Name in the console
and to `PRIVILEGE_MCPGW_URL` in `demo_api_server/.env`.

## Kubernetes

No counterpart file — ingress-nginx is the nginx engine there and
[`k8s/aws/mcpgw-agentless-ingress.yaml`](../k8s/aws/mcpgw-agentless-ingress.yaml)
carries the same directives as annotations. Keep the two in sync.
