Concept: Same 3 routes as Alt B, but adds a request timeline showing the full journey (prompt → intent → exchange → response). Includes intent token in the flow.
  • Pro: Shows the FULL security chain — intent extraction, token binding, exchange, RS response.
  • Pro: API RS keeps vertical-specific data with the timeline showing the credential swap.
  • Pro: "Full Token Chain" button links to the existing token chain page for deep-dive.
  • Con: More info density — might overwhelm non-technical viewers.
  • Compromise: Timeline could be collapsed by default, expanded on click.

Recommendation

Alt B (Split View) is the cleanest for demos. Alt C adds intent token visibility but can be collapsed.
  • All alternatives keep vertical-specific data on the API RS page (healthcare records, work orders, permits, etc.)
  • The 3 RS pages share a generic shell — vertical data is injected by query param.
  • Agent navigation: after tool call, window.location = '/rs/api?vertical=healthcare' instead of returning to chat.
  • Each vertical has 1 UC that navigates to the appropriate RS page (9 verticals × 1 = 9 navigations across 3 pages).

Service rename plan (next restart):
  • demo_mcp_invest → demo_mcp_resource_server (dir, Docker service, package.json name)
  • demo_mortgage_service → demo_api_resource_server (dir, Docker service, package.json name)
