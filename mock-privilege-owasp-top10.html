3 · The ten categories

ASI01–ASI10, explained with Privilege coverage

Each card explains the threat in plain language, names the Privilege component that covers it, and describes how the coverage works. Cards marked with a gap chip carry the honest remainder.

ASI01 · Agent Goal Hijack

CoveredAIGuard

An attacker smuggles instructions into content the agent reads — a poisoned web page, a document, an email, a hidden prompt — and steers the agent away from its real goal. The agent obeys the attacker's goal instead of the user's, and may start calling tools toward it.

How Privilege covers it: Injection, jailbreak and hidden-instruction detection. AIGuard inspects prompts and retrieved content before the agent acts, so smuggled instructions are caught at the input boundary instead of becoming agent behaviour.

ASI02 · Tool Misuse & Exploitation

CoveredAIGuard

The agent has powerful tools — file access, command execution, HTTP fetch — and a hijacked or confused agent turns them against the system: path traversal to read files it should not, destructive shell commands, SSRF to reach internal services, or calls beyond the scope it was granted.

How Privilege covers it: Path traversal, destructive command, SSRF and over-broad-scope rules. Requests to use a tool are evaluated against these rule classes before execution, so a poisoned agent cannot weaponise its toolset.

ASI03 · Identity & Privilege Abuse

CoveredGateway + AIGuard

Agents act with credentials. If an agent holds a shared admin key, or keeps privileges after the task is done, a compromise becomes a privilege compromise: the attacker inherits everything the agent could do. This is the classic over-privileged service account problem, reborn for agents.

How Privilege covers it: Per-user virtual keys, least-privilege scopes, RBAC and live revocation. Every agent call is re-bound to the human it acts for and narrowed to the scopes that call needs; keys can be revoked the moment abuse is detected.

ASI04 · Agentic Supply Chain

Gap statedAIGuard

The agent's capabilities arrive from outside: MCP tool definitions, plugins, fetched packages. A malicious tool definition (instructions hidden in a tool's description) or a typosquatted tool name installs attacker behaviour into the agent before it ever runs.

How Privilege covers it: Tool-definition injection and typosquatting detection. Tool metadata is scanned before it reaches the agent. Fingerprint pinning — locking an agent to the exact tools it was built against — is the stated remaining gap.

Gap: Fingerprint pinning is pending: today the gateway detects malicious tool definitions and typosquats, but does not yet pin a verified tool fingerprint per agent.

ASI05 · Unexpected Code Execution

CoveredAIGuard

Model output or retrieved content contains executable payloads: shell metacharacters that break out of a command, template-injection syntax that escapes a template engine, or a fetch-and-execute chain that downloads and runs attacker code.

How Privilege covers it: Shell metacharacter, template-injection and fetch-and-execute rules. Code-shaped content is inspected before it is passed to anything that would execute it.

ASI06 · Memory & Context Poisoning

Gap statedAIGuard

Agents persist what they learn. An attacker who plants a fact, preference or instruction into the agent's memory or context window changes every future decision the agent makes — a single write today becomes a standing backdoor across sessions.

How Privilege covers it: Memory-write inspection is shipped: content written into agent memory is inspected for poisoned instructions before it is stored.

Gap: Gateway integration is in progress: the memory-write inspection runs in AIGuard today; wiring the same inspection into the gateway path so all memory writes are covered is the remaining work.

ASI07 · Insecure Inter-Agent Communication

CoveredGateway + AIGuard

Multi-agent systems talk to each other. Without authenticated, scoped channels, any agent (or anything pretending to be one) can inject messages, impersonate a peer, or escalate by asking a more privileged agent to do its dirty work.

How Privilege covers it: The gateway is the A2A chokepoint: agent-to-agent traffic passes through it with a dedicated inter-agent scope, so a peer cannot be reached out-of-band, and inter-agent abuse rules inspect what agents ask of each other.

ASI08 · Cascading Agent Failures

CoveredGateway

Agents call agents call tools. One runaway or hallucinating agent can amplify through the chain — retry storms, cost blowouts, loops of tool calls — until a small failure becomes an outage or a runaway bill.

How Privilege covers it: Rate and budget ceilings, a circuit breaker, and an event stream to your SIEM. The gateway caps what any one agent can consume, cuts the circuit when a chain misbehaves, and streams the evidence to observability.

ASI08 is met by real-time event data to your observability stack; in-gateway behaviour scoring supplements ASI08 and ASI10.

ASI09 · Human-Agent Trust Exploitation

CoveredAIGuard

Humans trust their agents. An attacker exploits that trust: jailbreak the agent, make it leak its system prompt or other users' data, exfiltrate secrets through its outputs, or abuse the human's willingness to approve whatever the agent asks.

How Privilege covers it: Shared jailbreak, exfiltration, prompt-leak and PII rules. Outputs are inspected before they reach the human, so the agent cannot be turned into an exfiltration or leakage channel.

ASI10 · Rogue Agents

CoveredGateway

Unregistered, unauthenticated or long-forgotten agents — shadow AI with a network connection. A rogue agent has no owner, no scope and no audit trail, and everything it touches is unaccountable.

How Privilege covers it: No agent reaches a model, tool or peer without a valid scoped key. The gateway simply refuses anything that cannot present one — registration through Privilege's agent registry is the only way onto the network.

4 · Two layers

Gateway and AIGuard, in one picture

Privilege's coverage is split across two enforcement layers, and the categories make the division visible.

The Gateway (identity & chokepoint)

The gateway sits between agents and everything they reach — models, tools, and peer agents. It enforces who the agent is and what it may do: per-user virtual keys (ASI03), the A2A chokepoint with a dedicated inter-agent scope (ASI07), rate and budget ceilings with a circuit breaker and SIEM event stream (ASI08), and the no-key-no-access rule that keeps rogue agents off the network (ASI10).

AIGuard (content & behaviour)

AIGuard inspects what flows through: prompts and retrieved content for injection and jailbreak (ASI01), tool-use requests against misuse rules (ASI02), tool definitions for supply-chain injection (ASI04), code-shaped payloads (ASI05), memory writes (ASI06), and outputs for exfiltration, prompt leakage and PII (ASI09).

Where they overlap

ASI03 (identity & privilege abuse) and ASI07 (inter-agent communication) need both: the gateway proves identity and enforces scope on the hop, while AIGuard inspects the content of what the (now-proven) agent is asking for. ASI08's event stream and in-gateway behaviour scoring supplement ASI08 and ASI10 with runtime signal.
